# Track Atlas — спецификация v0.1

**Статус:** проектная спецификация, 2026-11-03. **Цель:** небольшой локальный каталог музыкальных референсов по жанрам и настроениям. Это требования к будущей реализации, не описание готовой функциональности.

## 1. Сценарий использования
Пользователь собирается создать новую композицию, знает примерный жанр и/или mood/vibe, открывает список фильтров и получает названия знакомых треков и исполнителей. Проигрыватель и управление файлами не нужны.

## 2. Границы MVP
**Обязательно:** настройка корневой директории; рекурсивное индексирование аудио; заголовок, исполнитель, альбом, существующий жанр; SQLite; список треков; поиск; множественные теги жанров и настроений; выбор чекбоксами; сохранение ручных изменений; массовая разметка; повторный скан.

**Опционально для первого релиза:** запуск AI-классификации выбранных треков через OpenRouter, предварительный просмотр предложений и подтверждение пользователем. Интеграция не должна блокировать работу без API-ключа.

**Не входит в MVP:** плеер, потоковая передача файлов, авторизация/многопользовательность, импорт Spotify/Яндекс Музыки, ML-аудиоанализ, постоянный Docker, Redis, MySQL, фоновая распределённая очередь, автоматическое создание неограниченных категорий.

## 3. Каталог и сканирование
- Пользователь задаёт локальный путь, проверяются существование и доступность чтения.
- Рекурсивный обход папки. Первоначальные форматы: MP3, FLAC, M4A, OGG; набор уточняется по возможностям парсера. Неподдерживаемые файлы пропускаются с отчётом.
- Поля: относительный путь, размер, mtime, название, исполнитель, альбом, сырой жанр, состояние файла, время последнего сканирования.
- При отсутствии тегов: попытка разобрать имя `Artist - Title`, иначе использовать имя файла и пометить недостаток метаданных.
- Повторный скан идемпотентен: неизменённые файлы не дублируются, изменённые обновляют **метаданные**, но не ручную классификацию.
- Пропавшие файлы помечаются отсутствующими, без автоматического удаления тегов. Перенос/переименование без стабильного идентификатора могут первоначально создавать новую запись; это задокументированное ограничение MVP.
- Аудиофайлы приложение не перемещает, не переписывает и не удаляет.
- Отчёт: просмотрено, добавлено, обновлено, пропущено, отсутствует, ошибки. Скан — отдельная Artisan-команда, запуск через UI возможен позднее.

## 4. Категории и фильтрация
- У каждого трека ноль или более жанров и ноль или более настроений.
- Для MVP `vibe` относится к типу `mood`; возможно выделение отдельного типа позже.
- Для выбора по нескольким жанрам действует **ИЛИ**; по нескольким настроениям **ИЛИ**; между выбранными наборами — **И**.
- Пустая группа фильтров не ограничивает результаты. Если обе группы пусты — показывать все треки.
- Поиск по подстроке названия и исполнителя, совместно с чекбоксами.
- Интерфейс отображает `Artist — Title`, теги и при необходимости альбом; сортировка по исполнителю/названию; желательно пагинация.
- Фильтр неразмеченных треков; добавление/переименование жанров и настроений; массовое назначение/удаление тегов.
- Единый справочник с уникальными нормализованными именами в пределах типа, поддержка алиасов по мере необходимости.

## 5. Приоритет пользовательской разметки
- Ручные назначения и ручные удаления должны быть защищены от повторного импорта.
- Источник каждого автоматического предложения сохраняется; предложения отделяются от подтверждённых связей.
- Даже если импортированный жанр совпадает с ручным, не создавать дубликат.
- Неакцептованные AI-предложения не обязаны влиять на фильтры; рекомендуемое правило: фильтровать по подтверждённым назначениям.
- Удаление тега самим пользователем нельзя отменять очередным автоматическим запуском без явного согласия.

## 6. AI-обогащение — следующая функциональная итерация
- Выбор треков/только незаполненных и явный запуск, с индикатором прогресса и возможностью остановки.
- Сначала существующие теги; затем OpenRouter LLM по названию, исполнителю, альбому и входным тегам.
- Perplexity Sonar / web search использовать точечно при недостатке данных; не обязателен для известных записей.
- Пакеты треков допустимы после оценки стабильности, ошибок и цены на пробных 20–30 примерах.
- Модель получает контролируемую таксономию, возвращает проверяемый JSON: идентификатор трека, genres[], moods[], объяснение/достоверность (если поддерживается). Отбрасывать невалидные и неизвестные ID, логировать ошибки.
- Сетевые обращения ограничивать по частоте, обрабатывать таймауты, повторы и частичное завершение. Запоминать обработанные записи и версию метода, чтобы не оплачивать одно и то же без необходимости.
- API-ключ — только в серверном `.env`, никогда в клиентском Vue, логах или Git.
- Предупреждать о передаче **метаданных** внешним поставщикам и о возможной стоимости. Аудио не отправлять без отдельного согласия.
- Классификация — предположение, не музыкальная истина. Пользователь утверждает или редактирует предложения.

## 7. Нефункциональные требования
- Ориентир: тысячи локальных файлов; UI не загружает сразу всю библиотеку.
- SQLite и приложение работают локально без Docker и без интернет-доступа для базовых функций.
- Ошибка чтения одного файла или сетевого API не прекращает весь процесс.
- Пути безопасно нормализуются; сканер ограничен выбранным корнем, предотвращает нежелательный обход через symlink.
- Тесты на фильтрацию, идемпотентность сканирования, приоритет ручных тегов и обработку плохих метаданных.

## 8. Критерии приёмки MVP
1. Индексировать тестовую папку с вложенными директориями и поддерживаемыми аудиофайлами.
2. Повторное сканирование без изменений не создаёт дублей.
3. Новый файл добавляется; изменённый получает обновлённые метаданные; удалённый помечается отсутствующим.
4. Разметка вручную сохраняется после повторного сканирования.
5. Один трек может иметь два жанра и три настроения.
6. Выбор `Darkwave OR Synthwave` и `Dark AND Melancholic` (для moods — OR, т.е. пример условного выбора настроений) даёт пересечение групп, а не общий OR.
7. Выбор только одного набора работает без второго; сброс показывает все доступные результаты.
8. Массовая разметка обновляет только выделенные треки.
9. Приложение полностью пригодно без OpenRouter, интернета, Python и Docker.
10. Приложение не изменяет исходные музыкальные файлы.

## 9. Вопросы до реализации
Точный перечень тегов, формат хранения алиасов, политика переименованных файлов и способ выбора внешней модели ещё не утверждены; использовать простые решения, допускающие изменение.


## 10. Требования к интерфейсу (уточнение от 2026-11-08)

- Vue 3, Tailwind CSS как основной набор стилей.
- shadcn-vue; все используемые компоненты должны располагаться **внутри проекта** (аналогично результату `npx shadcn-vue@latest add ...`).
- Иконки из `@lucide/vue`.
- **Любые параметры фильтрации — в URL**: жанры, настроения, поиск, отсутствие разметки и страница списка. Ссылка должна воспроизводить выбранный набор фильтров после перезагрузки, в другом окне и при переходах назад/вперёд.
- Светлая тема **по умолчанию**. Тёмная тема необязательна. Если появится переключатель тем, выбранное значение хранить в `localStorage`.
- Массовое редактирование тегов и явная индикация выделенных композиций.
