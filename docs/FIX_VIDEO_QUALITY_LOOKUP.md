# Исправление поиска по названиям видеоклипов без скобок

Пример из пользовательской библиотеки:

- исходные метаданные: `artist=HDFactory`, `title=PAIN - Shut Your Mouth HQ HD 4K`;
- метаданные, **отправляемые AI**: `artist=PAIN`, `title=Shut Your Mouth`.

Раньше `TrackLookupMetadata` извлекал артиста из видеозаголовка лишь при наличии `Official Video` / похожих пометок. Последовательности качества `HQ HD 4K` в конце названия не учитывались.

Теперь при наличии явного `Исполнитель - Песня` и **как минимум двух** следующих подряд обозначений качества (HQ/HD/4K/8K/1080p/720p) очистка удаляет эти суффиксы, а исполнитель из заголовка подставляется вместо имени канала. Одиночное `HD` у обычного названия не удаляется; `Song (Live)` и `Song - Part Two` сохраняются.

Оригинальные записи SQLite и файлы не меняются. Реального вызова OpenRouter тесты не делают.

## Локальная проверка

```bash
git fetch origin
git switch fix/video-quality-suffix-lookup
php -l app/Services/TrackLookupMetadata.php
php artisan test --filter=TrackLookupMetadataTest
php artisan test
```

**Проверка выявила пропуск 1/1:** прежнее AI-предложение было закэшировано, поэтому новая очистка названия не применялась к платному запросу. Добавлено отдельное действие **«Повторить выбранные AI-предложения»**, которое передаёт `retry_existing=true` и позволяет явный платный повтор для `pending` / `rejected` даже при непустых жанрах или настроениях. `accepted` всегда пропускается. Исходное предложение заменяется новым `pending` после успешного ответа. Обычная классификация и кнопка повторения только пустых предложений сохраняют прежнюю защиту от повторных затрат.

Сначала проверьте `php artisan test --filter=OpenRouterClassificationTest` и `npm run build`, затем на выбранном треке нажмите именно кнопку **«Повторить выбранные AI-предложения»**. Это может стоить денег. Успех распознавания зависит от модели.

## Если тесты возвращают HTTP 419 и SQLite database is locked

Если все POST/PUT feature-тесты дают 419 и `MusicScannerTest` пытается записать в `database/database.sqlite`, это признак того, что Laravel тестируется с неправильной конфигурацией (например, из `bootstrap/cache/config.php`). **Не повторяйте полный тестовый прогон, пока не исправите изоляцию.**

В ветке добавлены принудительные переменные `phpunit.xml` и защитная проверка в `tests/TestCase.php`: она откажется выполнять тесты, если `APP_ENV` не `testing` или SQLite не `:memory:`.

Выполните **вне тестового запуска**:

```bash
php artisan config:clear
php artisan test --filter=OpenRouterClassificationTest
php artisan test
```

Если защитная проверка остановит тесты с `Unsafe test environment`, проверьте `bootstrap/cache/config.php` и значения среды. Не меняйте рабочий `DB_DATABASE` в `.env` на `:memory:`: это требование только к тестам.

## Пустой экран Vue

Не считайте это ошибкой API, пока неизвестно состояние сборки. Выполните `npm run build` и проверьте вкладку Console браузерных DevTools на ошибки JS/Vue/Vite; пришлите сообщение и файл/строку. После переключения ветки проверьте, что сервер Vite, если используется `npm run dev`, запущен и страница загружает актуальные ресурсы. Для быстрого восстановления можно переключиться на проверенную ветку `main`, не удаляя SQLite и `.env`.
