# Страница референсов: фильтры, режим «и/или», критерии приёмки

**Статус:** спецификация к реализации, 2026-11-09. Задача `t_433d7027`.
**Область:** страница `/` (`ReferencesPage`) после переработки. Код не описывает; API-изменения — только контракт.
**Источник требований:** задача `t_433d7027` (уточнения Андрея) и существующие `docs/SPECIFICATION.md` §4, `docs/FRONTEND.md`, `docs/API.md`.

Все решения, которых не было в задаче, помечены **[решение]** — их можно переопределить до старта реализации.

## 1. Цель страницы

Пользователь создаёт новый трек, знает жанр и/или настроение и получает список названий знакомых треков как референсы. Страница — справочник, а не плеер и не редактор. Разметка (ручная, AI) на этой странице не выполняется.

## 2. Структура страницы

- Одна колонка, сверху вниз:
  1. блок **«Жанры»**;
  2. блок **«Настроения»**;
  3. блок **«Треки»** (список результатов).
- Сайдбара нет. Ни слева, ни справа.
- Дополнительных кнопок на странице нет, кроме перечисленных в §2.1 и §6.
- Заголовков страницы и вводных текстов нет. Единственный текст: подписи блоков, подписи элементов, состояния из §6.
- Ширина колонки: до 720 px, по левому краю **[решение]**. На мобильном — на всю ширину.

### 2.1. Что убрано с этой страницы

Эти элементы исчезают с `ReferencesPage` **[решение]**:

| Элемент | Судьба |
| --- | --- |
| Поле поиска | убрано со страницы (в задаче не упомянуто, блоков три) |
| Select «Полнота разметки» (`untagged`) | убран со страницы |
| Чипы активных фильтров | убраны |
| Кнопка «Сбросить» в шапке фильтров | заменена: сброс виден только в состоянии «пустой результат» (§6.3) |
| Выбор сортировки, направления и размера страницы | убран; берутся значения по умолчанию: `artist asc`, `per_page=30` |
| Переключатель плотности, копирование ссылки, кнопки панели фильтров на мобильном | убраны |
| Массовые действия, выделение строк, редактирование тегов | убраны (на страницы разметки) |

API эти параметры **не теряет**: `search`, `untagged`, `sort`, `dir`, `per_page` остаются (§7). Удаляется только UI этой страницы.

Пагинация внизу списка **сохраняется**: без неё нельзя дойти до треков сверх первой страницы (библиотека — 1435 треков). Это часть блока «Треки», не отдельная кнопка.

## 3. Блоки «Жанры» и «Настроения»

### 3.1. Общее

- Источник значений: `GET /api/tags` с фильтром по типу — жанры (`type=genre`), настроения (`type=mood`).
- Подпись элемента — русское название тега (`tagLabel`); если его нет, — английское.
- Порядок элементов: по подписи, по алфавиту (русская сортировка, без учёта регистра) **[решение]**. Порядок ответа API не используется.
- Каждый элемент — чекбокс с подписью. Количество треков у элемента **не показывается**.
- Блок прокручивается внутри себя, если элементов больше, чем помещается; высота ограничена примерно 14 rem **[решение]**.
- Выбранные элементы — в том же порядке, что и весь список (не поднимаются наверх).
- Блок открыт всегда, сворачивания нет.

### 3.2. Переключатель «и / или»

Переключатель находится в заголовке блока, справа от подписи блока.

- Вид: сегментированный переключатель из двух значений: **«или»** и **«и»**.
- Значение по умолчанию: **«или»**.
- Отдельный переключатель для каждого блока: один для жанров, один для настроений. Режимы независимы.
- Доступен всегда, в том числе при пустом выборе и при одном выбранном значении. Неактивным его не делаем **[решение]**.
- Меняет режим немедленно: без кнопки «Применить», список перезагружается сразу.
- Смена режима сбрасывает страницу на 1.
- Подписи для вспомогательных технологий: «Режим выбора жанров: или / и» и «Режим выбора настроений: или / и».

#### Что означает каждый режим

Пусть в группе выбраны значения `A`, `B`, `C`.

| Режим | Трек проходит фильтр группы, если… | Пример: выбраны `Darkwave` и `Synthwave` |
| --- | --- | --- |
| **или** | у трека есть **хотя бы одно** из выбранных значений группы | трек с `Darkwave`, или с `Synthwave`, или с обоими |
| **и** | у трека есть **все** выбранные значения группы (возможны и другие значения сверх них) | только трек, у которого есть и `Darkwave`, и `Synthwave` |

Режим действует **только внутри своей группы**. Между группами всегда действует **И** (§4).

При одном выбранном значении режимы дают одинаковый результат.

### 3.3. Выбор и снятие значений

- Клик по чекбоксу добавляет или убирает значение. Дубликатов нет.
- Значение можно снять, не трогая режим.
- Очистка группы — снятие всех её чекбоксов. Отдельной кнопки «очистить группу» нет **[решение]**.
- Снятие всех значений группы возвращает группу в состояние «пустая группа» (§5).
- Режим не сбрасывается при опустошении группы: после нового выбора он остаётся прежним.

---

## 4. Взаимодействие фильтров

1. Результат = треки, которые проходят **все непустые группы**. Группа проходит, если выполнено её правило (или/и из §3.2).
2. Между группами — всегда **И**: трек должен пройти фильтр жанров **и** фильтр настроений.
3. Пустая группа не ограничивает результат.
4. Оба блока пусты — показываются **все треки** каталога, включая треки без единой метки.
5. Режимы групп не влияют друг на друга.
6. Примеры:
   - жанры `Darkwave` + `Synthwave`, режим «или»; настроения пусты → все треки с `Darkwave` или `Synthwave`;
   - жанры `Darkwave` + `Synthwave`, режим «и»; настроения пусты → треки, где есть оба жанра;
   - жанры `Darkwave`, настроения `Melancholic` + `Dark`, режим настроений «и» → треки с `Darkwave`, у которых есть и `Melancholic`, и `Dark`;
   - жанры `Darkwave` + `Synthwave` (режим «или»), настроения `Dark` + `Melancholic` (режим «или») → треки, которые имеют (`Darkwave` или `Synthwave`) **и** (`Dark` или `Melancholic`).
7. Количество выбранных значений в группе не ограничено сверху.

---

## 5. Пустой выбор

- Ни один чекбокс не выбран — группа не фильтрует.
- Если обе группы пусты, список показывает все треки каталога (в том числе без жанров и настроений), сортировка по умолчанию.
- Режим «и» при пустой группе не даёт пустого результата: группа просто не участвует.
- Состояние «ничего не выбрано» не имеет отдельного текста.

## 6. Состояния

### 6.1. Загрузка справочника тегов (жанры и настроения)

- В каждом блоке вместо чекбоксов — три серых полоски-заглушки и скрытая для экрана подпись «Загрузка жанров…» / «Загрузка настроений…».
- Переключатель режима в этом состоянии **показан**, но недоступен (`disabled`) **[решение]**.
- Список треков при этом не блокируется: если треки уже загрузились, они отображаются.
- Выбранные значения из URL применяются к чекбоксам после загрузки справочника.

### 6.2. Ошибка загрузки справочника

- В блоке — сообщение об ошибке с одной кнопкой «Повторить» (повторяет запрос `/api/tags`).
- Текст ошибки — один, без технических деталей: «Не удалось загрузить жанры» / «Не удалось загрузить настроения».
- Переключатель режима — недоступен.
- Ошибка одного блока не блокирует другой блок и список треков.

### 6.3. Пустой результат

- Блок «Треки» показывает одну строку: «Ничего не подходит под выбранные фильтры».
- Ниже — одна текстовая кнопка «Сбросить фильтры»: снимает все значения обоих блоков и возвращает режимы к «или» **[решение]**.
- Пагинация скрыта.

### 6.4. Пустой каталог

- Если `total = 0` без фильтров: «В каталоге пока нет треков». Кнопки «Сбросить» нет.

### 6.5. Загрузка списка треков

- При смене фильтров, режима или страницы предыдущие строки остаются видимыми, но приглушены (`opacity` около 0.5) и помечены `aria-busy="true"` **[решение]**. Это исключает «мигание» пустого списка.
- При первой загрузке страницы (нет данных) — три заглушки строк.

### 6.6. Ошибка загрузки списка треков

- Блок «Треки» показывает: «Не удалось загрузить треки» и кнопку «Повторить».
- Фильтры и режимы остаются в том состоянии, в котором были.
- Старые строки не показываются, чтобы не вводить в заблуждение.

### 6.7. Неизвестные значения в URL

- Неизвестный `genres[]` / `moods[]` (id не из справочника своего типа) — при загрузке справочника тихо убирается из состояния страницы и из адреса.
- Неизвестный `genres_mode` / `moods_mode` (не `or` и не `and`) — трактуется как `or`.
- Нечисловые значения в `genres[]` / `moods[]` игнорируются.
- Такой параметр не вызывает ни ошибки, ни пустой страницы.

## 7. Список треков

### 7.1. Строка

- Строка показывает **только**: название трека, жанры трека, настроения трека.
- Исполнитель, альбом, длительность, путь к файлу, кнопки действий — **не показываются** (по задаче). **[решение, см. §10]**
- Жанры и настроения трека — подписи тегов через запятую или чипы, без кнопок и без ссылок.
- Строка без жанров и без настроений — выводит только название.
- Длинное название переносится на несколько строк; обрезания многоточием не допускается.

### 7.2. Порядок и пагинация

- Порядок по умолчанию: `artist asc`, `title asc`, `tracks.id asc` (как в API сейчас). Пользователь не выбирает порядок на этой странице.
- Пагинация: `per_page=30`, фиксирован.
- Внизу списка: «Назад», номер текущей страницы из общего количества, «Вперёд». Текст вида «страница 2 из 48» — допустим **[решение]**.
- Переход на другую страницу прокручивает к верху списка.

### 7.3. Контракт данных

- Список строится из `GET /api/tracks` с параметрами, описанными в §8.
- На этой странице исполнитель не выводится, но сортировка по исполнителю сохраняется (см. §10).

## 8. Состояние в URL и контракт API

### 8.1. Параметры URL страницы

| Параметр | Значение | По умолчанию (не пишется в URL) |
| --- | --- | --- |
| `genres[]` | id тегов типа `genre` | пусто |
| `moods[]` | id тегов типа `mood` | пусто |
| `genres_mode` | `or` или `and` | `or` |
| `moods_mode` | `or` или `and` | `or` |
| `page` | номер страницы, начиная с 1 | 1 |

Правила:
- Значение режима пишется в адрес, только если оно не по умолчанию (`and`). Адрес с режимом по умолчанию выглядит как раньше.
- Смена фильтра или режима пишет страницу 1 (параметр `page` удаляется).
- Адрес читается при открытии страницы и при `popstate`. Кнопки «назад» / «вперёд» восстанавливают и фильтры, и режимы, и страницу.
- Прямая ссылка воспроизводит состояние после перезагрузки.
- Поиск, `untagged`, `sort`, `dir`, `per_page` на этой странице **не пишутся** в адрес. Если они пришли в адресе, страница их игнорирует.

Пример:
```
/?genres%5B%5D=1&genres%5B%5D=2&genres_mode=and&moods%5B%5D=5&page=2
```

### 8.2. Изменение `GET /api/tracks`

Добавляются два параметра (остальные без изменений, см. `docs/API.md`):

| Параметр | Значение | Поведение |
| --- | --- | --- |
| `genres_mode` | `or` (по умолчанию) или `and` | `or` — есть хотя бы одно из `genres[]`; `and` — есть все `genres[]` |
| `moods_mode` | `or` (по умолчанию) или `and` | то же для `moods[]` |

- Значение вне `or` / `and` — `422` с `errors`, как у остальных параметров.
- Режим без соответствующего списка (`genres_mode=and` без `genres[]`) — не ошибка, фильтра нет.
- Дубликаты id в `genres[]` / `moods[]` сворачиваются до уникальных **до** подсчёта. Иначе режим «и» даст неверный результат.
- Режим «и» реализуется как «число совпавших выбранных тегов группы у трека = число уникальных выбранных тегов группы» (агрегация по трекам). Тип тега учитывается: только `genre` для `genres[]` и только `mood` для `moods[]`.
- Между группами — всегда И, как сейчас.
- Пустой результат — `200` с пустым `data`, а не `404`.
- Для групп с режимом по умолчанию (`or`) поведение не меняется: существующие ссылки и тесты остаются валидными.

### 8.3. Что обновить в документации (не в этой задаче)

Сейчас документы фиксируют «OR внутри группы» как постоянное правило. После введения режима их нужно поправить в том же PR, что и изменение API:

- `docs/SPECIFICATION.md` §4 (строка «Для выбора по нескольким жанрам действует **ИЛИ**…»): OR — режим по умолчанию, режим «и» доступен через переключатель.
- `docs/SPECIFICATION.md` §8, критерий 6: текущая формулировка («`Dark AND Melancholic` (для moods — OR…)») противоречива. Заменить примером, согласованным со §4 этой спецификации.
- `docs/FRONTEND.md`, строка «Сервер фильтрует по правилу OR внутри группы…»: описать `genres_mode` / `moods_mode`.
- `docs/API.md`, таблица параметров (строки `genres[]`, `moods[]`): добавить `genres_mode`, `moods_mode`.
- `docs/ROADMAP.md`, пункт «Фильтры-чекбоксы genre и mood, OR внутри / AND между»: дополнить «режим или/и по группе».

## 9. Критерии приёмки

### 9.1. Дизайнер

- [ ] Страница — одна колонка; сайдбара и правой панели нет.
- [ ] Порядок блоков: «Жанры», «Настроения», «Треки».
- [ ] На странице нет поиска, выбора разметки, сортировки, размера страницы, чипов, переключателя плотности, кнопки копирования ссылки.
- [ ] Переключатель «или / или» — сегментированный, в заголовке своего блока, визуально отличается от чекбоксов. Активное значение заметно без цвета (например, фон или подчёркивание).
- [ ] Состояния зафиксированы в макете: загрузка (заглушки), ошибка с «Повторить», пустой результат с «Сбросить фильтры», пустой каталог, загрузка списка (приглушённые строки).
- [ ] Строка трека: название + жанры + настроения. Длинные названия переносятся, не обрезаются.
- [ ] Текст на странице — только подписи из этой спецификации; заголовков и пояснений нет.
- [ ] Светлая тема по умолчанию (`docs/SPECIFICATION.md` §10). Тёмная тема на этой странице не вводится.
- [ ] Макет проверен на ширинах 360 px и 1280 px; колонка не растягивается шире 720 px на широком экране.

### 9.2. Программист

- [ ] Режимы `genres_mode` / `moods_mode` читаются из URL и отправляются в `/api/tracks`; по умолчанию не пишутся в адрес.
- [ ] Смена фильтра, режима или страницы — один запрос, без гонок: ответ устаревшего запроса не перетирает новый (отмена или проверка актуальности).
- [ ] Дубликаты id в `genres[]` / `moods[]` сворачиваются на клиенте и на сервере.
- [ ] Неизвестные id тегов и неизвестные значения режима обрабатываются по §6.7 без ошибок в консоли.
- [ ] Кнопки «назад» / «вперёд» восстанавливают фильтры, режимы и страницу (`popstate`).
- [ ] Удалённые из страницы элементы (поиск, `untagged`, сортировка, плотность, чипы) не рендерятся. Код, который они использовали в API, не удаляется.
- [ ] Для групп тегов нет запросов `/api/tags` при каждом изменении фильтра: справочник загружается один раз; повторная загрузка — только по кнопке «Повторить».
- [ ] API: `genres_mode=and` возвращает только треки со всеми выбранными жанрами; `or` — как раньше.
- [ ] Тесты API: режимы по умолчанию, `and` с 1 и 2+ значениями, дубликаты id, невалидный режим → `422`, пустой результат → `200`, смешанный запрос (and в одной группе, or в другой, между группами И).
- [ ] Тесты UI (или ручная проверка, если UI-тестов нет): переключение режима сбрасывает страницу; состояния §6 отображаются.
- [ ] `pint`, `npm run build`, `php artisan test` проходят на dev-окружении (PHP 8.4 по умолчанию).

### 9.3. Тестировщик

- [ ] Выбор одного жанра: режимы «или» и «и» дают одинаковый список.
- [ ] Выбор `Darkwave` + `Synthwave`, режим «или» → треки с любым из двух; режим «и» → только треки с обоими. Проверить на треке, у которого оба жанра, и на треке с одним.
- [ ] Жанр и настроение выбраны, оба режима «или» → пересечение групп. Смена режима одного блока не меняет результат другого блока.
- [ ] Обе группы пусты → все треки каталога, включая без меток; количество совпадает с `total` без фильтров.
- [ ] Пустой результат → текст §6.3, кнопка «Сбросить фильтры» возвращает все значения и режимы «или».
- [ ] Ссылка с режимом `and` открывается в новом окне и показывает тот же результат и переключатели в том же положении.

## 10. Открытые решения (принятые в спеке, требуют подтверждения Андрея)

1. **Исполнитель в строке.** В задаче сказано «трек показывает только название, жанры и настроения». `docs/SPECIFICATION.md` §4 предполагает «Artist — Title». Спека следует задаче: только название. Если исполнитель нужен для различения треков с одинаковым названием, это отдельное изменение.
2. **Поиск и «Полнота разметки» убираются** со страницы, хотя в `docs/SPECIFICATION.md` §4 они упомянуты как функции. Спека следует формулировке «три блока». Если поиск нужен, он добавляется как поле над блоком «Жанры» и не меняет описанное выше.
3. **Сортировка и размер страницы** на этой странице не выбираются (значения по умолчанию). API сохраняет возможности.
4. **Кнопка «Сбросить фильтры»** видна только в пустом результате. Постоянной кнопки сброса нет.
5. **Переключатель режима доступен всегда**, даже при одном значении (там он ничего не меняет).

## 11. Вне объёма

- Сохранение фильтров в `localStorage` (запрещено `docs/FRONTEND.md`: источник — URL).
- Счётчики треков у значений.
- Смешанный режим внутри одной группы (например, «A или B и C»).
- Пересечение групп через «или» между блоками (между группами всегда «и»).
- Поиск, сортировка, редактирование тегов на этой странице.
- Тёмная тема.
