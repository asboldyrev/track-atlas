# PR #6 — выборочное принятие AI-предложений и работа с категориями

## Возможности

### Выборочное подтверждение тегов

Внутри карточки ожидающего предложения OpenRouter появились отдельные чекбоксы у каждого предложенного жанра и настроения. Изначально выбраны все. Можно снять часть флажков и нажать «Принять», тогда в `track_tag` будут добавлены **только оставленные метки**. Если снять все, предложение помечается принятым, но к треку ничего не добавляется. Кнопка «Отклонить» по-прежнему отклоняет всё предложение.

В API `PUT /ai/suggestions/{id}` добавлены необязательные массивы `genres[]` и `moods[]` в JSON. Без них действует прежнее поведение — принять всё. С ними сервер сверяет каждую выбранную строку с исходным предложением (без учёта регистра, но **без принятия произвольных новых значений**), так что подмена запроса не позволяет создать лишний тег. Жанры нормализуются по существующему словарю. Состояние предложения остаётся `accepted` / `rejected`; перечень изначально предложенных категорий сохраняется для истории.

### Повторная классификация вручную

Новая кнопка «Повторить выбранные AI-предложения» отправляет **платный** запрос только для выделенных треков, имеющих предложения в состоянии `pending` или `rejected`. Результаты с `accepted` никогда не перезаписываются. Для обычных новых композиций используется прежняя кнопка; повтор только пустых предложений также сохранён.

Платная обработка, как и прежде, выполняется пакетами до 10 треков, с подтверждением и возможностью остановить следующие партии.

### Объединение дублирующихся жанров и настроений

В боковой панели есть форма «Объединить дубли категорий». Сначала выбирают исходную категорию, затем целевую **того же типа**. После подтверждения:

- все связи исходной категории с треками переносятся на целевую;
- если целевая связь уже есть, дубль связи не создаётся; ручной источник `manual` имеет приоритет;
- русское название переносится на целевой тег только если у него нет своего;
- исходная категория удаляется; процедура выполняется в транзакции;
- URL текущей страницы обновляется, заменяя исходный ID в фильтрах на целевой.

**Важно:** ранее скопированные URL, содержащие ID удалённого тега, не могут автоматически обновиться. При объединении пользователь получает предупреждение. Объединяйте только категории, которые действительно означают одно и то же. Исходные аудиофайлы не изменяются.

## Локальная проверка

```bash
git fetch origin
git switch feat/selective-ai-review
php artisan optimize:clear
php artisan test
npm run build
```

Миграций и новых npm-зависимостей в этом PR нет. Проверить интерфейс можно без дополнительных AI-вызовов:

1. Найти `pending` предложение с несколькими жанрами и настроениями; снять часть чекбоксов и принять. Убедиться, что появились только отмеченные категории.
2. Найти две **тестовые** категории одного типа. Объединить их и убедиться, что все прежние треки имеют целевую метку. Попытку объединить жанр с настроением UI не предлагает, API вернёт 422.
3. Проверить фильтрацию через URL, переводы, ручное редактирование тегов и массовое назначение.
4. Кнопка «Повторить выбранные AI-предложения» требует подтверждения и **может тратить деньги**. На уже принятом предложении повтор должен пропускаться. Нет необходимости запускать платный тест, если сценарии с моками прошли.

## Ограничения

- Ручное редактирование трека после принятия предложения сохраняет прежнюю модель поведения.
- Для выбранных, но не принятых меток не сохраняется отдельный статус отклонения каждой метки. Предложение считается обработанным целиком.
- Перепроверка с моделью возможна только для `pending` и `rejected`. Платная попытка может вернуть пустой или ошибочный результат.
- Объединение удаляет старую категорию и может потребовать обновления ранее сохранённых ссылок с её ID; автоматических постоянных редиректов нет.
- UI остаётся на Vue 3 + Tailwind CSS, локальных shadcn-vue-компонентах и Lucide, светлая тема по умолчанию.
