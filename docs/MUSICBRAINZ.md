# PR #4 — предложения жанров из MusicBrainz

Этот этап **не изменяет назначенные трекам категории при обращении к MusicBrainz**. Дополнительно вводится небольшой справочник алиасов жанров для ручного создания категорий и импорта жанров из локальных файлов. Он находит возможное соответствие в базе MusicBrainz и сохраняет предложенные жанры отдельно — для будущего просмотра и подтверждения в интерфейсе.

## Настройка

В локальном приложении Docker не требуется. Примените миграции:

```bash
php artisan migrate
php artisan test --filter=MusicBrainzEnrichmentTest
```

## Пробная обработка

Для тестирования только нескольких композиций, у которых есть исполнитель и название:

```bash
php artisan music:enrich --limit=5
```

Для одной конкретной записи, если известен ID трека:

```bash
php artisan music:enrich --track=123
```

Повторная проверка ранее обработанных:

```bash
php artisan music:enrich --track=123 --force
```

**Никакой массовой автоматической обработки**: команда запускается вручную, по умолчанию выбирает только первые 10 ещё не проверенных треков, `--limit` ограничен 1–30. Результаты сохраняются в `metadata_suggestions` (provider, recording_mbid, match_score, genres, status). Категории `track_tag` не меняются. При ручном редактировании ничего не пропадает.

## Сопоставление

1. Поиск записи MusicBrainz по названию и исполнителю.
2. Берётся только результат со score не меньше 90 и точным совпадением названия и artist credit после нормализации регистра и пробелов. Это намеренно строгая проверка: некоторые реальные релизы могут быть пропущены, зато риск приписать жанры другому треку ниже.
3. По MusicBrainz recording MBID читаются **genres**; учитываются жанры с положительным счётчиком.
4. Если запись не опознана, статус `unmatched`; если найдена, но у самой записи нет жанров, `matched_no_genres`; если жанры есть, `pending`. Во всех случаях результат кэшируется и не запрашивается повторно без `--force`.

Названия с распространёнными пометками видео (`Official Video`, `Official Music Video`, `4K Upgrade`) очищаются **только для поиска**. В SQLite исходные названия не меняются. Поиск по-прежнему строгий: featuring-исполнители, нестандартные artist credit и разные написания могут быть пропущены.

**Важно:** у MusicBrainz жанры часто указаны у исполнителя или альбома, но отсутствуют на уровне recording. Статус `matched_no_genres` в таком случае нормален. Привязывать артистские жанры к конкретному треку автоматически пока не будем. Позже можно получать их как более слабые предложения с явно указанным источником и сравнить качество с OpenRouter.

## Нормализация жанров

Словарь `config/genre_aliases.php` приводит известные написания к одному названию: например `Synth-pop` и `Synthpop` → `synthpop`; `DnB` и `Drum & Bass` → `drum and bass`. Новые варианты добавляются вручную после проверки. Уже созданные в базе категории автоматически не переименовываются и не объединяются.

## Ограничения и безопасность

- Название и исполнитель передаются в публичный API MusicBrainz **только по явной команде**.
- Нужен интернет. По правилам MusicBrainz используется осмысленный User-Agent и интервал не менее 1.2 секунды между HTTP-запросами.
- При HTTP 429/502/503/504 выполняются не более двух дополнительных попыток с увеличивающейся паузой. При окончательной ошибке запись не сохраняется как обработанная, чтобы её можно было повторить.
- Нет вызовов OpenRouter, отправки аудио и автоматического принятия результатов.
- Для продакшена или коммерческого использования нужно отдельно ознакомиться с условиями API MusicBrainz.

Источник: https://musicbrainz.org/doc/MusicBrainz_API и https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting .

## Повторная проверка после исправления поиска

Для уже проверенных ранее треков (их результаты закэшированы) используйте `--force` с конкретным ID:

```bash
php artisan music:enrich --track=6 --force
php artisan music:enrich --track=8 --force
```

Не запускайте массовый `--force --limit=30` до просмотра результатов нескольких известных треков.
