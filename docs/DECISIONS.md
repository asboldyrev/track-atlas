# Предыстория и принятые решения

Сводка обсуждения 2026-11-03. Это **содержательный перенос договорённостей**, а не дословный экспорт переписки.

## Проблема
Большая коллекция разножанровой музыки нужна как **справочник референсов** при создании новых треков. При возникновении идеи известен жанр, mood/vibe или оба. Требуются прежде всего **название и исполнитель**, а не проигрывание или перенос файлов. Изначально рассматривались обычные текстовые списки, но выбран небольшой веб-инструмент на Laravel + Vue.

## Согласованные решения
- Простое локальное приложение, минимум «наворотов».
- Рекурсивный просмотр песен в заданной папке, создание БД и повторное сканирование изменений.
- Чекбоксы жанров и настроений; множественный выбор, комбинированная фильтрация; список подходящих треков.
- Несколько жанров и настроений у трека; ручная и массовая разметка, особенно для незаполненных moods.
- SQLite вместо отдельного сервера БД. getID3 — предложенный парсер тегов.
- Жанры из файлов легко получить, **mood/vibe обычно не содержится** в тегах; для него требуется ручная или AI-разметка.
- Псевдонимы жанров нужно нормализовать: Synth-pop / Synthpop / Synth Pop.
- Пользовательская разметка приоритетнее автоматической; сохранять источник и по возможности степень уверенности.
- **Laravel + Vue работают на локальном компьютере без Docker.** Docker допустим исключительно как опциональный инструмент для будущего анализа аудио через Python/Essentia. Устанавливать Python локально пользователь не хочет.
- Музыка **почти вся известная**, доступна в Spotify, Яндекс Музыке или подобных сервисах; редких треков немного. Это усиливает пользу LLM-классификации по метаданным.
- OpenRouter — основной кандидат для AI: названия/артисты/альбомы → genres/moods и структурированный JSON. Допускается обработка пакетами после пробного теста.
- Essentia / MTG-Jamendo mood/theme и genre-модели — возможный третий этап, не стартовый функционал. Аудиоанализ через облачные модели также рассматривался, но дороже и требует согласия на передачу аудио.
- Автоматическое массовое обогащение без контроля нежелательно; сначала тестировать порядка 20–30 разных треков и оценить качество/стоимость.
- Предлагались названия `music-reference-finder`, `vibe-index`, `track-atlas`, `sound-reference`, `moodtrack`; фактически выбран и создан репозиторий **`asboldyrev/track-atlas`**.

## Обсуждённые примеры
Жанры: Synthwave, Darkwave, Synthpop, Rock, Ambient, Electronic, Metal, Orchestral.
Mood: Melancholic, Dark, Epic, Dreamy, Energetic, Romantic, Mysterious, Aggressive.
Атмосферные понятия: Cyberpunk, Rainy Night, Nostalgic 80s, Post-apocalyptic.
Это иллюстрации, не обязательный окончательный словарь.

## Рассмотренные, но отложенные идеи
- Определение треков по акустическому отпечатку AcoustID/Chromaprint при плохих именах.
- Анализ самого аудио через Essentia/Python в разовом Docker-контейнере.
- Audio-capable LLM через OpenRouter.
- Отдельная сущность vibe вместо объединения с mood.
- Стриминговые интеграции и полноценный плеер.

## Неутверждённые детали
Точные категории и локализация, поставщик/модель LLM, бюджет API, поведение при переименовании файла, способ отбора/принятия AI-тегов. Их нужно уточнить по результатам MVP и пробной классификации, не усложняя старт.

## Принятые решения по реализации (2026-11-09)

- **Интеграция фронтенда: Blade mount + JSON API. Inertia не используется.** Laravel отдаёт Blade-страницы с точкой монтирования, Vue 3 собирается Vite и получает данные из JSON API. Причина: серверные фильтры каталога, пагинация и отдельные мутации через POST/PUT проще и предсказуемее описываются обычным JSON-контрактом, а Blade-страница оставляет каталог работоспособным без сборки клиентского бандла. Inertia добавила бы собственный канал передачи пропсов и не давала бы выигрыша при уже реализованном API (`/catalog`).
- **Базовая версия PHP — `^8.4.1`.** Столько требуют зависимости из `vendor` (16 пакетов с `>=8.4.1`), поэтому `composer.json` приведён к этой границе; более старые PHP в `require` оставлять нельзя.
- **Тесты не зависят от локального `.env`.** `APP_KEY` для прогона задан в `phpunit.xml`; тестовая среда использует sqlite `:memory:`. Свежий клон без `.env` даёт зелёный `php artisan test`.
- **Индексы под каталог:** `tracks(is_missing, artist, title)`, `track_tag(tag_id, track_id)`, `metadata_suggestions(provider, status)` — миграция `2026_11_09_120500_add_lookup_indexes.php`.
- **MusicBrainz удалён из проекта.** Причина: на практике оказался не полезен — жанры часто отсутствуют на уровне recording (`matched_no_genres`), покрытие реальных треков низкое. Источник и вся интеграция удалены: клиент `MusicBrainzClient`, команда `music:enrich`, тесты и документация. Таблицу `metadata_suggestions` с накопленными данными сохраняем; её удаление — отдельным шагом после бэкапа.
